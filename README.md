# КОНТУР · 1.6.0 — Workflow и доверенная автономность

Локальный интерактивный прототип: React, Node.js и SQLite. В архиве находятся исходники, готовый `dist/`, тесты и пошаговый `DEMO_SCRIPT.md`.

## Запуск

Нужен Node.js 24 с npm. Полностью распакуйте архив, откройте терминал в папке приложения и выполните:

```sh
npm start
```

Откройте `http://127.0.0.1:3000`. Устанавливать npm-зависимости для этого запуска не требуется: интерфейс уже собран, сервер использует встроенные модули Node.js. Остановка — Ctrl+C.

На Node.js 22.16, использованном для проверки в среде сборки, сервер и тесты запускались с явным `--experimental-strip-types`. Для обычного использования оставлена исходная версия окружения проекта — Node.js 24; её фиксирует `.nvmrc`.

```sh
# Альтернативный запуск на проверенном Node.js 22.16:
node --experimental-strip-types server/index.mjs
```

## Данные и начало демо

Исходная папка `data/` из приложенного архива сохранена вместе с SQLite WAL. Это сохраняет существующую демонстрационную историю. Не удаляйте отдельный WAL-файл, пока приложение работает. При первом чтении выполняется добавочная миграция v16: новые платформы, судья, Knowledge MCP и второй регулятор. Старые snapshots, запуски и отчёты не переписываются.

Для нового показа выберите **«Открыть настройку с нуля»**. Если этот сценарий уже заполнен, откройте меню `⋯` → **«Очистить настройку с нуля»** и подтвердите удаление именно его данных. Сценарий «С данными» хранится отдельно.

Нулевой экран объясняет весь путь и роли. На главной и под рабочими экранами находится гид со следующим доступным действием. Кнопка перехода предлагает нужного участника. Роль также можно сменить в верхней панели.

## Что изменено

**Настройка.** Сначала продукт и команда, затем участники, платформа, её доступы и инфраструктура. Только после этого — доска, восемь задач, пакет регулятора и Workflow. Поле команды называется «Ответственность команды». Доступны HG SDLC (исходное название), Maestro и AI Conductor. AI Manager виден, но недоступен. Выбор платформы и ресурсы защищены проверками Platform Engineer на сервере. При смене платформы требуется переподключение её ресурсов.

**Политики.** Регулятор создаёт пакет с предзаполненным правилом обновления зависимостей; навыки и субагенты выбираются вручную. Историю изменений можно оставить пустой. Автор сохраняется в пакете. Изменять статус может только другой регулятор нужного направления — four-eyes проверяется не только кнопкой, но и API. Сегментация систем находится у регулятора.

**Workflow.** Создание начинается в «Автоматизации», где появились список сценариев и кнопка «Создать Workflow». Доска не создаёт Workflow. Сохранение изменений создаёт новую версию. Исправлена проверка последовательности дополнительных Implementation/Checks, блокировавшая допустимый изменённый сценарий. Диалог запуска расширен; слева оставлен ответственный за проверку и, при необходимости, причина запрета.

**Benchmarks.** Набор строится из успешно завершённых задач с фактическими артефактами. Мастер: задачи → судья. Судья хранится как версия промпта и выходной схемы; отдельная вкладка «Судьи» позволяет создать новую версию. Оценка повторяет сохранённый Workflow в изолированной копии состояния, затем сравнивает результат с эталоном. Таблица содержит две строки на задачу — эталон и проверяемый запуск — с точной версией Workflow, полнотой, корректностью, покрытием тестами, критическими уязвимостями и ошибками. Исходные задачи не меняются.

**Выпуск.** Перед фиксацией проверяется успешная история этой конфигурации; бенчмарк рекомендован, но не превращён в обязательный запрет. Подходящий успешный отчёт выбирается по умолчанию, выбор можно снять. Дальше следуют UAT, решение Product Owner о риске, выпуск Product Engineer и наблюдение. Новый пакет политики требует нового кандидата и перевыпуска, не меняя действующий снимок.

**Знания.** Оставлены онтология, отдельные review и публикация, дерево и граф опубликованных знаний. «Доставка агенту» объясняет MCP и будущий API, но не запускает отдельную симуляцию. Knowledge MCP выполняется в журнале Workflow на Implementation: текст задачи → план потребностей → запрос → фрагменты → доставка. Для обновления зависимости показаны командное правило Jenkins и обязательные политики сегмента, а отсутствие нужды в продуктовых знаниях объяснено. Источники и версии закрепляются в снимке запуска.

## Граница прототипа

MCP, LLM, Git, Jenkins, оркестраторы, UAT и production execution остаются **демонстрационной симуляцией**, а не внешними интеграциями. Реально работают интерфейс, доменная логика, ограничения ролей, переходы состояний, версии, SQLite и аудит.

Судья детерминированно сравнивает операции фактического diff с сохранённым эталоном и учитывает результат проверок. Покрытие тестами и безопасность — отдельные помеченные fixtures симулятора; они не выдаются за реальные замеры CI или сканера. Свободный промпт судьи сохраняется, но внешняя LLM его не исполняет. Две успешные задачи подходят для демонстрации пути, но не являются доказательством промышленной безопасности автономного исполнения.

Старые тестовые наборы без сохранённого эталонного diff не получают выдуманный PASS: создайте новую версию набора из завершённых запусков. Новые опубликованные знания подключаются выбором актуальных версий Product/Team Knowledge в общих настройках нового Workflow; уже зафиксированные запуски и выпуски их автоматически не подхватывают.

## Разработка и тестирование

Полная стандартная сборка с доступом к реестру npm:

```sh
npm ci
npm run build
npm run dev
```

Основные тесты не требуют React/Vite и работают с готовым архивом:

```sh
npm test
# Для Node.js 22.16:
node --experimental-strip-types --test tests/runtime.test.mjs tests/domain.test.mjs tests/api.test.mjs tests/setup.test.mjs tests/journey-v16.test.mjs
```

После `npm ci` отдельно доступны `npm run test:render` и `npm run test:dev`. Отчёт о реально выполненных проверках — `TESTING.md`.

`npm run build:offline` пересобирает код приложения с установленным TypeScript и включённым закреплённым runtime. Это способ получить сборку без загрузки библиотек; он проверяет синтаксис, но **не заменяет** полный `npm run typecheck`. Подробности — `vendor/runtime/README.md`.

Настройки: `HOST` (по умолчанию `127.0.0.1`), `PORT` (3000), `DATA_FILE` (`data/kontur.sqlite`). Приложение предназначено для локального демо, а переключатель ролей не является промышленной аутентификацией. Не публикуйте его в открытый интернет как рабочую систему.
