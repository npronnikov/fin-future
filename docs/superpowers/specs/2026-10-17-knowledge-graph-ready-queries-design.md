# Готовые запросы к графу знаний

## Цель

Добавить в раздел «Управление знаниями» демонстрационное выполнение готовых Cypher-запросов и показывать фактический запрос к графу внутри события доставки знаний на таймлайне запуска.

Функция остаётся честной JavaScript-эмуляцией: приложение не подключается к Neo4j и не принимает произвольный Cypher.

## Пользовательский сценарий

Во вкладке «Граф знаний» пользователь выбирает один из четырёх готовых запросов:

1. опубликованные знания продукта;
2. практики текущей команды;
3. знания и связанные с ними понятия;
4. контекст для этапа Implementation.

Интерфейс показывает текст Cypher, выполняет соответствующий детерминированный обход текущего state приложения и выводит найденные узлы. Нажатие на результат открывает уже существующую карточку знания или понятия.

В таймлайне запуска внутри раскрытия «Доставка знаний · Knowledge MCP» пользователь видит Cypher-запрос, его параметры и возвращённые фрагменты. Для демонстрационного запуска `RUN-912` это позволяет проследить путь от запроса до данных, доставленных в Implementation.

## Архитектура

Готовые запросы и их эмуляторы хранятся в общем модуле. Каждый preset содержит стабильный идентификатор, пользовательское название, текст Cypher и функцию выборки из вычисленного графа либо state приложения.

Экран графа использует этот модуль для выбора запроса и отображения результатов. Формирование immutable receipt запуска использует тот же preset для записи текста запроса и параметров. Это не связывает интерактивное состояние экрана с уже созданным запуском: receipt фиксирует запрос в момент доставки.

Существующая функция построения графа остаётся источником узлов и связей. Формат графа расширяется только в случае, если результатам нужны недостающие метаданные; отдельное хранилище не создаётся.

## Интерфейс графа

Под существующей визуализацией появляется карточка «Готовые запросы»:

- переключатель четырёх preset-запросов;
- read-only блок с Cypher;
- кнопка «Выполнить учебный запрос»;
- количество результатов и список найденных объектов;
- явная подпись «JavaScript-эмуляция Cypher · без подключения к Neo4j».

До выполнения результата нет. При смене preset предыдущий результат очищается. Пустой результат отображается как нормальное состояние, а не как ошибка.

## Доставка знаний в Run

Receipt Knowledge MCP получает два новых поля:

- `graphQuery` — точный Cypher-запрос;
- `queryParams` — параметры текущего продукта, команды, сегмента и целевого этапа.

Существующее текстовое описание потребности Planner сохраняется отдельно и не выдаётся за Cypher. Компонент деталей доставки сначала показывает запрос и параметры, затем знания продукта, команды и обязательные политики.

Для старых сохранённых запусков, в которых `graphQuery` отсутствует, интерфейс использует существующее поле `query` и не падает.

## Ошибки и границы

- Произвольный ввод Cypher не поддерживается.
- Эмулятор выполняет только известные preset-запросы.
- Неопубликованные знания не возвращаются.
- Командные знания ограничиваются текущей командой.
- Политики сегмента продолжают добавляться независимо от решения Planner.
- Пустой набор результатов не блокирует интерфейс; receipt сохраняет фактически найденные фрагменты.

## Проверка

Доменные тесты проверяют, что каждый preset возвращает только допустимые опубликованные данные и соблюдает product/team scope.

Render-тест таймлайна `RUN-912` проверяет наличие Cypher-запроса, параметров и доставленных фрагментов внутри disclosure Knowledge MCP. Существующие тесты публикации знаний, графа и запуска должны продолжить проходить.

## Критерии приёмки

- Во вкладке «Граф знаний» доступны четыре готовых запроса.
- Пользователь видит Cypher до запуска и результаты после нажатия кнопки.
- Результаты соответствуют текущему продукту и команде.
- В `#/run/RUN-912/` запрос виден внутри события доставки знаний.
- Интерфейс явно сообщает, что используется эмуляция без Neo4j.
- Старые receipts без новых полей отображаются без ошибки.
